# 11. MCP Write Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Claude create, edit, move, change status of, delete, and comment on Driftboard cards through the local MCP server, as the signed-in user, behind an opt-in flag.

**Architecture:** A `DriftboardWriter` interface (mirroring `DriftboardReader`) with a Firebase-backed implementation that resolves card -> list -> board, checks `canPerformAction`, then calls `lib/firebase-service.ts` with `{ source: "mcp" }`. Card position logic moves out of the board page into `cardService.moveCard`, so the UI and the MCP share one move path that writes history and activity.

**Tech Stack:** TypeScript, Firebase client SDK (Firestore), `@modelcontextprotocol/sdk`, zod, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-28-mcp-write-tools-design.md` (approved 2026-11-03). Epic: `v0-driftboard-u36`.

---

## Problem Statement

The MCP server can read Driftboard but not change it, so Claude workflows can report on boards but can't triage them. Separately, the board page renumbers cards with `reorderCards`, which writes no history or activity, so drag-and-drop moves leave no audit trail and the position logic lives in UI code no other client can reuse.

## Requirements

- Six tools: `create_card`, `update_card`, `move_card`, `set_card_status`, `delete_card`, `add_comment`.
- Registered only when `DRIFTBOARD_MCP_WRITE=1`; otherwise the server stays read-only.
- Writes allowed wherever the user's role permits (`lib/permissions.ts`), including shared boards.
- `delete_card` is a soft delete with `destructiveHint: true`; other write tools `destructiveHint: false`.
- MCP writes stamp `source: "mcp"` on history entries and activity `details` (not on `_current` docs).
- Errors: not-found and no-access look the same (`<Thing> <id> not found, or you don't have access.`); role refusals name the board and role; cross-board moves refused.
- `cardService.moveCard` renumbers source and destination lists to contiguous `0..n-1`, clamps position, omitted position = bottom, one history entry + one `MOVE_CARD` activity. Board page drag-and-drop uses it.
- `createCard` with no position appends at the bottom; restoring a card to `active` appends it at the bottom.

## Technical Approach

See the spec for the full design. Decisions made while planning, beyond the spec:

- **Board resolution uses `getUserBoards` + `getBoardLists`, not `getBoardRole`.** `getUserBoards` already returns only active boards with `userRole` and `title`, which gives the role check, the error message, and deleted-board exclusion in one call - the same visibility rule `get_card` uses since the deleted-board fix. Extracted to `mcp/visibility.ts` (`findVisibleList`) and shared by reader and writer.
- **Sibling renumbering reads outside the transaction.** Firestore client-SDK transactions can only `get` document refs, not run queries, so `moveCard` queries the active cards of both lists inside the transaction callback (non-transactionally) and writes all new positions in the transaction. A concurrent move in the same list can leave a gap or duplicate; the next move in that list renumbers it away. Acceptable for a personal app.
- **Only changed siblings are written.** Renumbering skips cards whose position is already right.
- **`reorderCards` is removed** once the board page stops calling it (no other callers). The `reorderCards` permission action stays - `card-item.tsx` uses it for UI gating.
- **There are no existing board page drag-and-drop tests** (the spec assumed there were). Coverage for the page change is the service tests plus the manual drag-and-drop checklist section.

```ts
  /**
   * Moves a card to `newListId` at `position` (clamped; omitted = bottom) and
   * renumbers active cards in the source and destination lists to 0..n-1.
   * Same-list moves reorder within the list. Writes one history entry for the
   * moved card and one MOVE_CARD activity.
   */
  async moveCard(
    cardId: string,
    userId: string,
    newListId: string,
    position?: number,
    options?: WriteOptions,
  ): Promise<void> {
    const cardRef = doc(db, "cards_current", cardId);
    const moved = await runTransaction(db, async (transaction) => {
      const docSnap = await transaction.get(cardRef);
      if (!docSnap.exists()) throw new Error("Card not found");
      const current = docSnap.data();
      const fromListId: string = current.listId;
      // Client-SDK transactions can't run queries, so sibling positions are
      // read outside it. A concurrent move can leave a gap; the next move in
      // that list renumbers it away.
      const others = (await cardService.getListCards(newListId)).filter(
        (c) => c.id !== cardId,
      );
      const index = Math.min(Math.max(position ?? others.length, 0), others.length);
      const destination = [...others.slice(0, index), null, ...others.slice(index)];
      const source =
        fromListId === newListId
          ? []
          : (await cardService.getListCards(fromListId)).filter(
              (c) => c.id !== cardId,
            );

      const stamp = { updatedBy: userId, updatedAt: serverTimestamp() };
      transaction.set(doc(collection(cardRef, "history")), {
        changeType: "update",
        subType: "move",
        createdAt: serverTimestamp(),
        createdBy: userId,
        snapshot: { ...current, listId: newListId, position: index, ...stamp },
        ...sourceField(options),
      });
      transaction.update(cardRef, { listId: newListId, position: index, ...stamp });
      const renumber = (cards: (Card | null)[]) =>
        cards.forEach((c, i) => {
          if (c && c.position !== i)
            transaction.update(doc(db, "cards_current", c.id), {
              position: i,
              ...stamp,
            });
        });
      renumber(destination);
      renumber(source);
      return { title: current.title as string, fromListId };
    });
    try {
      const listSnap = await getDoc(doc(db, "lists_current", newListId));
      if (listSnap.exists())
        await activityService.logActivity({
          boardId: listSnap.data().boardId,
          userId,
          action: "MOVE_CARD",
          details: {
            cardId,
            cardTitle: moved.title,
            fromListId: moved.fromListId,
            toListId: newListId,
            ...sourceField(options),
          },
        });
    } catch (e) {
      console.error("Activity log error:", e);
    }
  },
```

export interface VisibilityServices {

  listService: Pick<typeof listService, "getBoardLists">;

  board: Board;
  list: List;
}

/**
 * Finds `listId` among the active lists of the user's active boards.
 * Rules can allow reading a card or list by id after its board is deleted or
 * the user is removed from it, so tools check this before trusting an id.
 */
export async function findVisibleList(
  services: VisibilityServices,
  userId: string,
  listId: string,
): Promise<ListLocation | null> {
  const boards = await services.boardService.getUserBoards(userId);
  for (const board of boards) {
    const lists = await services.listService.getBoardLists(board.id);
    const list = lists.find((l) => l.id === listId);
    if (list) return { board, list };
  }
  return null;
}

import {
  boardService,
  listService,
  cardService,
  commentService,
} from "@/lib/firebase-service";
import { canPerformAction } from "@/lib/permissions";
import type { Card } from "@/lib/types";
import { toCardSummary } from "./firebase-reader";
import { findVisibleList, type ListLocation } from "./visibility";
import {
  WriteError,
  type CardUpdates,
  type DriftboardWriter,
  type WrittenCard,
} from "./writer";

export interface WriterServices {
  boardService: Pick<typeof boardService, "getUserBoards">;
  listService: Pick<typeof listService, "getBoardLists">;
  cardService: Pick<
    typeof cardService,
    | "getCard"
    | "createCard"
    | "updateCard"
    | "updateCardStatus"
    | "moveCard"
    | "deleteCard"
  >;
  commentService: Pick<
    typeof commentService,
    "createComment" | "getCardComments"
  >;
}

const defaultServices: WriterServices = {
  boardService,
  listService,
  cardService,
  commentService,
};

const MCP_SOURCE = { source: "mcp" } as const;
const WRITABLE_STATUSES: readonly Card["status"][] = [
  "active",
  "done",
  "archived",
];

// Permission action -> phrase for "can't ..." errors.
const VERBS = {
  createCard: "create cards",
  updateCard: "edit cards",
  moveCard: "move cards",
  deleteCard: "delete cards",
  addComment: "comment",
} as const;
type WriteAction = keyof typeof VERBS;

const notFound = (what: "Card" | "List", id: string) =>
  new WriteError(`${what} ${id} not found, or you don't have access.`);

function isPermissionDenied(error: unknown): boolean {
  return (error as { code?: string })?.code === "permission-denied";
}

function toWrittenCard(card: Card): WrittenCard {
  return {
    ...toCardSummary(card),
    listId: card.listId,
    createdAt: card.createdAt,
  };
}

// Firestore rejects undefined field values, so drop fields the caller left out.
function definedOnly(updates: CardUpdates): CardUpdates {
  return Object.fromEntries(
    Object.entries(updates).filter(([, value]) => value !== undefined),
  ) as CardUpdates;
}

/**
 * DriftboardWriter backed by the Firebase client SDK, acting as `userId`.
 * Checks the user's role first for clear errors; Firestore rules still enforce
 * access. Every write is stamped `source: "mcp"` in history and activity.
 */
export function createFirebaseWriter(
  userId: string,
  services: WriterServices = defaultServices,
): DriftboardWriter {
  const requireList = async (listId: string): Promise<ListLocation> => {
    const location = await findVisibleList(services, userId, listId);
    if (!location) throw notFound("List", listId);
    return location;
  };

  const requireCard = async (cardId: string): Promise<ListLocation> => {
    const card = await services.cardService.getCard(cardId);
    const location =
      card && WRITABLE_STATUSES.includes(card.status)
        ? await findVisibleList(services, userId, card.listId)
        : null;
    if (!location) throw notFound("Card", cardId);
    return location;
  };

  const requireRole = ({ board }: ListLocation, action: WriteAction) => {
    if (!canPerformAction(board.userRole, action))
      throw new WriteError(
        `Your role on "${board.title}" (${board.userRole ?? "none"}) can't ${VERBS[action]}.`,
      );
  };

  const readBack = async (cardId: string): Promise<WrittenCard> => {
    const card = await services.cardService.getCard(cardId);
    if (!card) throw notFound("Card", cardId);
    return toWrittenCard(card);
  };

  // Rules denying a write look the same as not-found, like the read tools.
  const guard = async <T>(
    what: "Card" | "List",
    id: string,
    write: () => Promise<T>,
  ): Promise<T> => {
    try {
      return await write();
    } catch (error) {
      if (isPermissionDenied(error)) throw notFound(what, id);
      throw error;
    }
  };

  return {
    createCard: ({ listId, title, description }) =>
      guard("List", listId, async () => {
        requireRole(await requireList(listId), "createCard");
        const cardId = await services.cardService.createCard(
          listId,
          userId,
          title,
          description,
          undefined,
          MCP_SOURCE,
        );
        return readBack(cardId);
      }),

    updateCard: (cardId, updates) =>
      guard("Card", cardId, async () => {
        requireRole(await requireCard(cardId), "updateCard");
        await services.cardService.updateCard(
          cardId,
          userId,
          definedOnly(updates),
          MCP_SOURCE,
        );
        return readBack(cardId);
      }),

    moveCard: (cardId, listId, position) =>
      guard("Card", cardId, async () => {
        const from = await requireCard(cardId);
        requireRole(from, "moveCard");
        const to = await requireList(listId);
        if (to.board.id !== from.board.id)
          throw new WriteError(
            `move_card can't move between boards (${from.board.title} → ${to.board.title}).`,
          );
        await services.cardService.moveCard(
          cardId,
          userId,
          listId,
          position,
          MCP_SOURCE,
        );
        return readBack(cardId);
      }),

    setCardStatus: (cardId, status) =>
      guard("Card", cardId, async () => {
        requireRole(await requireCard(cardId), "updateCard");
        await services.cardService.updateCardStatus(
          cardId,
          userId,
          status,
          MCP_SOURCE,
        );
        return readBack(cardId);
      }),

    deleteCard: (cardId) =>
      guard("Card", cardId, async () => {
        requireRole(await requireCard(cardId), "deleteCard");
        await services.cardService.deleteCard(cardId, userId, MCP_SOURCE);
        return readBack(cardId);
      }),

    addComment: (cardId, content) =>
      guard("Card", cardId, async () => {
        requireRole(await requireCard(cardId), "addComment");
        const commentId = await services.commentService.createComment(
          cardId,
          userId,
          content,
          MCP_SOURCE,
        );
        const comments = await services.commentService.getCardComments(cardId);
        const comment = comments.find((c) => c.id === commentId);
        if (!comment)
          throw new Error(`Comment ${commentId} not readable after create`);
        return {
          id: comment.id,
          content: comment.content,
          author: comment.user.displayName || comment.user.email,
          createdAt: comment.createdAt,
        };
      }),
  };
}

- **Manual:** Task 5 step 5 (drag-and-drop after the page change) and Task 12 (prod run-through, audit trail, shared board, drag-and-drop checklist).
- **Emulator integration:** write cases (viewer refused by rules, editor allowed on a shared board, renumbering against real Firestore, `source` on history) go into `v0-driftboard-u36.4`; not blocking this plan.

## Risks & Mitigation

| Risk                                                           | Mitigation                                                                                                                      |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Drag-and-drop regression from the page switching to `moveCard` | Service tests for renumbering; manual check in Task 5; drag-and-drop checklist in Task 12                                       |
| Concurrent moves leave gaps or duplicate positions             | Next move in the list renumbers; ordering is by position so gaps are harmless. Revisit with realtime sync (`v0-driftboard-ec5`) |
| Agent writes to prod by mistake                                | Opt-in flag, Claude Code permission prompts (`destructiveHint` on delete), soft delete, `source` marker in history              |
| Client-written audit trail can be forged                       | Known (`v0-driftboard-tg2`); a backend owns history once the hosted API (`v0-driftboard-8fi`) exists                            |
| Extra reads per write (all boards' lists)                      | Acceptable for personal data sizes; documented in Known limits                                                                  |
