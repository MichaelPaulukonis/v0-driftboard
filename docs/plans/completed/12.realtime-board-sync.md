# 12. Realtime Board Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Synchronize active lists and cards across browser tabs, shared-board collaborators, and MCP write tools in real time on the board page using Firestore `onSnapshot` listeners.

**Architecture:** Add `listService.subscribeBoardLists` and `cardService.subscribeListCards` in `lib/firebase-service.ts` so UI components remain decoupled from Firestore APIs. Move subscription management into a new `hooks/use-board-realtime.ts` hook that dynamically attaches/detaches per-list card listeners as lists come and go, while deferring incoming snapshot renders during active drag-and-drop gestures or in-flight move transactions. `app/board/[id]/page.tsx` consumes the hook and drops its one-shot list/card fetch loop.

**Tech Stack:** TypeScript, Next.js 15 (App Router), React 19, Firebase client SDK (`onSnapshot`), Vitest, React Testing Library.

**Bead:** `v0-driftboard-ec5`

## Problem Statement

Opening the same board in two tabs (or across multiple users on a shared board, or alongside Claude MCP write tools) does not reflect changes made in the other session until the page is manually reloaded. `app/board/[id]/page.tsx` currently fetches lists and cards once on mount (and after local dialog callbacks) via `getDocs`. Additionally, `README.md` previously claimed real-time synchronization and had those lines removed in commit `4054fc9` until real-time sync is actually built.

## Requirements

- **Service-layer encapsulation:** All Firestore `onSnapshot` calls live in `lib/firebase-service.ts`. UI components never import `firebase/firestore` directly.
- **Minimal subscription scope:**
  - `listService.subscribeBoardLists(boardId, onLists, onError?)`: subscribes to active lists (`lists_current` where `boardId == boardId`, `status == "active"`, ordered by `position asc`). Returns an `Unsubscribe` function.
  - `cardService.subscribeListCards(listId, onCards, onError?)`: subscribes to active cards for a single list (`cards_current` where `listId == listId`, `status == "active"`, ordered by `position asc`). Returns an `Unsubscribe` function.
- **Per-list card listeners (dodges `in` cap):** Subscribing per list reuses the existing `(listId, status, position)` composite index and avoids the 30-item Firestore `in` query limit (`v0-driftboard-kle`).
- **Dynamic listener lifecycle:** When a list is added on the board, `BoardPage` subscribes to its cards; when a list is deleted/removed, `BoardPage` unsubscribes that list's card listener immediately; when `BoardPage` unmounts or `boardId`/`user` changes, all list and card listeners are cleaned up.
- **Timestamp safety:** Pending local writes (`serverTimestamp()`) can temporarily yield `null` for `createdAt`/`updatedAt` in immediate local snapshots before latency compensation resolves. Snapshot mappers must fall back to `new Date()` when `toDate()` is nullish (`(data.createdAt as Timestamp)?.toDate?.() ?? new Date()`).
- **DnD & in-flight mutation reconciliation (Option B):**
  - Track `isDraggingRef` (from `@atlaskit/pragmatic-drag-and-drop` `onDragStart` / `onDrop`) and `pendingMovesRef` (counter of in-flight `reorderLists` / `moveCard` calls).
  - While `isDraggingRef.current || pendingMovesRef.current > 0`, stash incoming snapshot updates in a ref instead of calling `setBoardState`, preventing mid-drag DOM unmounts and `runTransaction` snap-back flicker.
  - When `isDraggingRef.current` is false and `pendingMovesRef.current` reaches `0` (in `finally`), flush any stashed snapshot state into `boardState`.
- **Restore `README.md` claims:** Restore the real-time collaboration bullets removed in `4054fc9` once the feature ships.
- **CHANGELOG:** Add a `CHANGELOG.md` entry (user-facing feature) per `.github/changelog-management.md`.

## Non-Goals

- **Board-level metadata sync:** Board title, description, and the viewer's `userRole` are loaded once on mount and not subscribed. Renames in another tab or role changes appear on reload. These change far less often than lists/cards; revisit as a follow-up if needed.

## Technical Approach

- **Snapshot mappers in `lib/firebase-service.ts`:** Extract small `toList(doc)` and `toCard(doc)` helpers in `lib/firebase-service.ts` with null-safe `Timestamp` conversion so `getBoardLists`/`subscribeBoardLists` and `getListCards`/`subscribeListCards` share identical mapping logic.
- **`useBoardRealtime` hook (`hooks/use-board-realtime.ts`):** Owns all subscription and deferral state so `page.tsx` stays focused on rendering and DnD wiring, and so the logic is testable with `renderHook` instead of rendering the full page.
  - Signature (indicative): `useBoardRealtime(boardId, enabled) => { boardState, setBoardState, loading, error, setDragging(bool), trackPendingMove(promise), resyncFromLatest() }`.
  - Maintains `cardUnsubsRef: Map<string, () => void>`, `latestListsRef: List[]`, `latestCardsByListRef: Record<string, Card[]>`, `initialCardSnapshotIdsRef: Set<string>`, `isDraggingRef`, `pendingMovesRef`, `hasDeferredSnapshotRef`.
  - **Building board state:** Compute `{ orderedColumnIds, columnMap }` from the latest refs. **Dedupe cards by id** across lists (first occurrence wins) - per-list listeners fire separately, so a remotely moved card can transiently appear in both source and destination lists and cause duplicate React keys.
  - **Deferral:** If `isDraggingRef.current || pendingMovesRef.current > 0`, set `hasDeferredSnapshotRef.current = true` and return; otherwise apply to `boardState`.
  - **Loading:** `loading` clears when the list snapshot has arrived and every list id in it is in `initialCardSnapshotIdsRef` (added on each list's first card snapshot). A list snapshot with zero lists clears `loading` immediately.
  - **Errors:** List-listener `onError` (e.g. `permission-denied` after membership revocation or board deletion) sets `error`; `page.tsx` reacts by `router.push("/")`, matching today's load-failure behaviour. Card-listener errors are logged and surfaced the same way.
- **`BoardPage` (`app/board/[id]/page.tsx`):**
  - Keep the one-shot `boardService.getUserBoards(user.uid)` check to verify board access, resolve `userRole`, and redirect to `/` if unauthorized or not found. Enable the hook only after verification.
- **Child component callbacks:** Props like `onListCreated`, `onListUpdated`, `onListDeleted`, `onCardUpdated`, `onCardRestored`, and `onListRestored` currently pass `loadBoardData` (which re-runs `getDocs` for everything). Replace with a module-level `noop`; listeners deliver those changes. Do **not** keep a `getDocs` refresh - it duplicates reads and a slower `getDocs` result can overwrite a newer snapshot, bypassing deferral. File a follow-up bead to remove the now-dead props from `ListColumn`, `CardItem`, and the dialogs.

```ts
// Pending serverTimestamp() writes surface as null in local snapshots.
const toDateOrNow = (value: unknown): Date =>
  (value as Timestamp | null | undefined)?.toDate?.() ?? new Date();

const toList = (docSnap: QueryDocumentSnapshot<DocumentData>): List => {
  const data = docSnap.data();
  return {
    id: docSnap.id,
    ...data,
    createdAt: toDateOrNow(data.createdAt),
    updatedAt: toDateOrNow(data.updatedAt),
  } as List;
};

const toCard = (docSnap: QueryDocumentSnapshot<DocumentData>): Card => {
  const data = docSnap.data();
  return {
    id: docSnap.id,
    ...data,
    createdAt: toDateOrNow(data.createdAt),
    updatedAt: toDateOrNow(data.updatedAt),
  } as Card;
};
```

Switch the existing getters to the mappers (no behaviour change for committed docs; they also stop throwing on null timestamps):

- `listService.getBoardLists`: `return snap.docs.map(toList);`

## Risks & Mitigation

- **`serverTimestamp()` nullability in local snapshots:** When the local client creates a list or card, Firestore fires local `onSnapshot` listeners immediately with `createdAt: null` / `updatedAt: null` before server acknowledgment. Calling `.toDate()` unconditionally throws `TypeError: Cannot read properties of null (reading 'toDate')`. Mitigated by `(data.createdAt as Timestamp)?.toDate?.() ?? new Date()`.
- **Stuck `pendingMovesRef` counter blocking snapshots:** If an error path in `reorderList`, `reorderCard`, or `moveCard` fails to decrement `pendingMovesRef`, live updates would stop for the session. Mitigated by wrapping the service promise tracking in a shared `trackPendingMove(promise)` helper using `.finally()`.
- **Orphaned card listeners when lists are deleted:** If a list is soft-deleted while the board is open, its card listener must be detached so memory and Firestore listeners don't leak. Mitigated by diffing `cardUnsubsRef` on every `subscribeBoardLists` emission and calling `unsub()` for any list ID no longer in the active list set.
- **Firestore `in` limit of 30 (`v0-driftboard-kle`):** Avoided entirely by subscribing per-list (`where("listId", "==", listId)`) rather than a board-wide `where("listId", "in", listIds)` listener.
- **Cross-list move shows card twice:** Source and destination list listeners fire separately; dedupe by card id when building board state.
- **Stale rollback:** Reverting to a captured `prevState` on move failure could discard snapshots received meanwhile; rebuild from latest snapshot refs via `resyncFromLatest()` instead.
- **Lost access mid-session:** Membership revocation or board deletion makes the list listener error with `permission-denied`; redirect to `/`.

## Dependencies

- Existing composite indexes in `firestore.indexes.json` already cover `lists_current` `(boardId ASC, status ASC, position ASC)` and `cards_current` `(listId ASC, status ASC, position ASC)` - no new Firestore index deployment required.
- Existing security rules in `firestore.rules` already grant `read` (`get` and `list`) on `lists_current` and `cards_current` to board owners and members.
